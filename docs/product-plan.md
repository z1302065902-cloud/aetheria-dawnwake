# 《AETHERIA · 破晓之誓》产品形态与路线图

> 定位：**单人幻想 RTS · 英雄领主**。不是"网页版魔兽争霸"。
> 卖点组合：**英雄 RPG + RTS 建造 + 即时战斗 + Boss + 装备 + Roguelite + 单人战役**。
> 本文档说明"这是什么产品"、"现在处于哪个阶段"、"下一阶段做什么"。

## 一、一句话定位

**你是一位英雄领主：英雄负责冒险，军队负责战争，基地负责成长。**

| 支柱 | 玩家做什么 | 系统 |
|---|---|---|
| **英雄** | 选英雄出征、升级、换装备、点天赋、探图拿遗物 | `data/heroes.ts` · `systems/Equipment` · `systems/HeroAbilities` · `systems/Adventure` |
| **军队** | 编组 + 姿态（跟随/守卫/自动进攻/驻守），一次下令长期生效 | `systems/ArmyGroups` |
| **基地** | 造建筑、自动生产、工人自动分配 | `systems/Build` · `systems/Production` · `systems/Automation` |
| **战役** | 三幕十关，主/支线/隐藏三档任务 | `data/missions.ts` · `systems/Mission` |

**控制优先级：英雄 > 军队 > 基地 > 经济**，玩家永远不需要当农民保姆。

## 二、为什么这个形态适合本作

经典 RTS（对战）需要：平衡性调优、多人网络、天梯匹配、反作弊 —— 都是长周期工程。
本作形态只需要：**内容 + 表现 + 手感**，且每一项都能被 AI 流水线批量生成：

| 需求 | 传统对战 RTS | 本作（英雄领主） |
|---|---|---|
| 平衡 | 100+ 单位必须两两平衡 | 英雄强度靠等级解决，允许"强" |
| 网络 | 必须做 | 不需要（单人） |
| 内容扩展 | 新单位要考虑全部克制关系 | 新英雄 = 一套技能 + 一套配色；新关卡 = 一份数据 |
| 商业化 | 外观/赛季 | 皮肤/战役包/DLC 都成立 |

## 四、下一步优先级建议

按"视觉/内容收益 ÷ 成本"排序：

1. **英雄皮肤系统**（第四阶段，性价比最高）
   程序化美术让皮肤 = 一套配色覆盖（`VisualBible` 的五层色）。3 英雄 × 3 皮肤 = 9 张 spritesheet，启动时生成。
   解锁条件可用星级（例：某关 3 星解锁）——天然与战役进度绑定。

2. **补 7 个英雄到 10 个**（第三阶段最大缺口）
   每个英雄 = 一份数据（基础属性 + 4 技能 + 配色 + archetype）。当前 3 个英雄已覆盖 坦克/法师/射手，
   建议补：圣骑士（治疗/护盾）、刺客（高爆发/隐身）、召唤师（召唤物）、工程师（炮台/陷阱）、
   野蛮人（狂怒/范围）、吟游诗人（增益）、德鲁伊（变形/自然）。

3. **7 张专属地图**（第三阶段）
   目前 10 关共用 3 套 biome 生成器 → 用 `MapGen` 的 biome 参数扩展出 10 套不同地貌主题
   （雪原 / 火山 / 沼泽 / 废墟 / 浮空岛…），每套有自己的区域色 + 天气 + 光照。

4. **结算页视觉化**（商业展示）
   现在胜利是文字面板 + 推镜；应做成"英雄立于战场 + 夕阳 + 城堡 + 旗帜 + 粒子"的画面。

5. **技能图标系统**（UI 材质化）
   圣经 §11 已定义"元素色底板 + 白色字形 + 径向冷却遮罩"，尚未实现。

## 五、已建立的工程基建（支撑后续批量扩展）

| 基建 | 作用 |
|---|---|
`src/art/VisualBible.ts` | **唯一色源**：128 色 + 五层色彩 + 比例 + 光照 + VFX + 材质 + 天气 + UI + 字体 + 图标 + 镜头
`src/systems/*` | 系统化架构：自动化 / 编组 / 冒险 / 事件 / 光照 / 迷雾 / 战役
`tests/*.mjs` | **可判失败的验证**：smoke 60 · visual 68 · campaign 51 · singleplayer 20 · product 11 · pacing 5 · layout 24 · soak 6
`tools/gen-visual-bible.mjs` | 文档从代码生成，规范不可能与实现脱节

> 原则：**新增内容必须服从 `VisualBible`**；任何视觉规则都要能在 `tests/visual.mjs` 里判失败。
